# Iteration 0002 — 统一设备体验与 iOS 环境

2026-11-17 用户明确要求补充 mini 环境并开始落地，实施 [PRD-002](../../prd/PRD-002-device-experience-ios/README.md)。状态：实施中。

## 当前批次

- A：统一真机／模拟器列表、状态、过滤和详情，收敛导航；隐藏的平台页不轮询。
- B：补充 iOS 宿主环境，提供明确的 WDA 前置条件和诊断；真机签名必须有实际证书依据。
- C：安装一个兼容的 Xcode／runtime，验证一个 iOS Simulator 的启动、操作与同实例重开。
- D：在 iOS 链路可用后采集基线；不预先承诺达到 Android 测量值。

## 实施约束

规范源码仍是本仓库；沿用已有数据库、设备别名、Agent 身份和 VM。初期读取视图关联现有资源，不合并实体表。
节点管理／跨区媒体直连暂缓。测试站保留免登录策略，机器令牌与设备租约继续生效。
Xcode 安装前核对 macOS 兼容与磁盘，使用 Apple 分发来源，保留原 CLT 路径供回退。
仅变更本服务，先测试、备份再更新；不通过重装设备或新建替代实例掩盖失败。

## 本轮取舍与证据

- Xcode 版本：原拟16.4，经用户指出后核对 [Apple 官方兼容表](https://developer.apple.com/xcode/system-requirements)，改用26.3；macOS保持15.6.1，不升级系统。
- 仅当前模拟器平台挂载；切平台会重置未提交表单，换取隐藏页无后台请求。后续如需要保留草稿，使用独立草稿存储，不能恢复三页同时轮询。
- 真实环境检查只覆盖宿主工具链／WDA工程／runtime／真机签名；配对与设备控制继续以现有设备探活为准，不把宿主检查当作完整WDA部署验收。
- iOS创建默认按Agent近期报告筛选；真正下发仍走现有Server preflight，不能绕过实时能力检查。
- 部署保留旧数据及Jack Agent/原Android VM；只重启中央服务与mini Agent，变更前确认无控制租约和运行任务。
- Windows原生界面工具曾因无法确认Apple页面URL终止，已停止该工具；用户随后完成26.3下载操作。自有测试站的页面检查继续复用既有CDP通道，未重建连接。

- 2026-11-17 浏览器检查：统一列表显示3个资源且无重复；iOS过滤只剩真机；详情原生dialog正常打开、关闭，环境检查可见；iOS平台只挂载1个创建表单，隐藏平台无请求。宿主报告在安装后自动更新为Xcode通过。

- 第一轮GitHub CI在 `add31ea` 全部成功：3305 passed、43 skipped、1 xfailed，362.52秒；前端128项和两个构建通过。随后修正安装后已选机型的runtime刷新默认值与重复创建保护，最终提交另核CI。
- Xcode26.3安装到 `/Applications/Xcode.app`，选择其Developer目录，内置签名验证与首次初始化通过；原CLT目录保留。首次按版本下载26.2 runtime后仍缺可用的构建平台；依Apple官方平台安装流程补充平台组件，安装器又提供26.3.1，之后xcodebuild能识别模拟器目标。两套runtime约15.6GB；不将一次下载结束当作WDA可用。
- 测试配置首次启动记录WDA目标不可用，修复环境后重试同一Server实例ID；尚未首次绑定成功前Agent清理了本次失败创建的空实例，不能将这段描述为已验证UDID跨失败保留。正式持久身份／应用数据验收从首次成功绑定后开始。

- 后续修复扫描结果中的“不完整”与“确认无设备”混淆；沿用上次身份并标记扫描不可信，实时探活失败仍立即降级。启动／重连保留已核实的实例名，继续校验端口上的WDA身份，不因瞬时simctl超时丢掉已知身份。
- 实测发现长原生诊断被写入VARCHAR(128)错误码导致500；错误码取有界前缀，完整诊断保留在错误消息与观察记录中，HTTP仍返回可解释的409。
- 两次成功停止／重开后原生UDID不变，WDA应用Documents内测试标记保留。第二轮宿主将设备Agent从Background调整为Interactive（launchd本机文档用于依赖响应性的服务）；当时既有PDF任务仍在运行，不能把启动耗时变化当作隔离对比。
- 控制证据与边界见[实际设备验证](../../validation/ios-0002/README.md)。源码、自动化、部署和用户验收分别记录；B/C/D仍有明确未验收项，本迭代不标整体完成。
