# PRD-002 — 统一设备管理与 iOS 使用体验

文档版本：0.2。日期：2026-11-17。状态：用户已授权开始落地，迭代 0002 实施中；实际验证和部署状态见迭代记录。

## 背景与目标

Android 低延迟链路已在 MVP 中落地，但管理页面仍继承较多 ai-phone 的组织方式。
当前设备数量少，最重要的是快速找到设备、理解状态、进入操作和恢复异常。
iOS 真机 WDA 与 iOS Simulator 必须同时纳入设计，避免先做 Android 页面、再为 iOS 另造一套后台。

目标：一个设备入口、一套占用规则、一个工作台；平台差异体现在能力与诊断中。
“界面统一”不等于将真机 USB/配对逻辑与 Simulator 生命周期混成同一个驱动。

## 来源与确认范围

用户明确：

- 现有 ai-phone 管理 UI 问题较多，需要优化。
- 节点管理可以暂缓，当前设备不多。
- iOS WDA 和 iOS 虚拟机／模拟器需要整合考虑。
- 可以将阶段优化记录为 PRD。
- 既有约束：Compact UI；前期测试站免浏览器登录；iOS 保留 WDA；人工与 Agent 共用占用机制。

用户随后明确要求补充 mini 安装环境并开始落地，已进入迭代 0002。
实施方案依实际环境细化；签名与工具链安装必须经过真实检查，不能以排期代替验收。

2026-11-17 对当前 mini 宿主的只读检查：开发目录仍为 CommandLineTools；
`xcodebuild -version` 无完整 Xcode，`xcrun simctl list runtimes -j` 找不到 simctl。

## 建议的信息架构

主入口收敛为“设备”和“任务”；应用、环境、宿主信息放入设备详情或设置。
保留旧路由的兼容跳转，避免历史书签失效。节点作为设备详情中的“运行位置”，不新增节点大盘。

```text
设备
  搜索  [全部 / Android / iOS]  [全部 / 真机 / 模拟器]  [+ 添加]
  名称          类型          系统        状态           主操作
  Android 测试  Android 真机   …           可操作         打开
  iPhone 测试   iOS 真机       …           缺少 WDA 环境  检查环境
  iOS 回归机    iOS 模拟器     …           已关机         启动

  设备详情：概况 | 环境与诊断 | 应用 | 操作记录
  工作台：画面 + 控制工具；任务、日志和诊断按需展开
```

例子为布局说明，不是实际存在的 iOS 模拟器。默认不展开硬件 ID、端口、完整日志或机型目录。
少量设备采用紧凑列表；缩窄窗口时变为同等信息层级的行卡片，而非强制横向大表格。

## 核心模型与状态规则

对用户统一为“设备资源”，在读取视图中关联现有记录；初期不迁移或合并驱动／实例表。

| 维度 | 建议内容 | 规则 |
|---|---|---|
| 稳定身份 | resource_id、platform_family、kind、instance_id、实际 serial/UDID | 模拟器关机前后保持同一资源；真机重连保留别名 |
| 连接／生命周期 | 离线、已连接、已关机、启动中、运行中、停止中、未知 | 运行中不等于 WDA 或画面已就绪 |
| 能力 | 可查看画面、可输入、可安装应用、可执行 Agent 任务、可启停 | 能力各自有原因，不能用一个 online 布尔值替代 |
| 占用 | 空闲、本人控制、他人控制、Agent 执行中 | 明确操作主体；未知占用者不能默认当成本人 |
| 健康／维护 | 正常、等待检查、失败、维护中 | 镜像暂停只是暂停镜像，不冒充整台设备的持久维护状态 |
| 证据时间 | 最近探测、当前操作、错误、检查阶段、更新时间 | 旧探测不覆盖新操作，不把连接断开显示为成功停止 |

列表只显示一个主状态和一个主动作；详情解释构成。展示优先级建议：
正在执行的生命周期操作 → 宿主离线／状态未知 → 缺失条件／故障 → 占用 → 可操作。
即使主状态显示故障，当前占用仍独立可见，且不能绕过占用执行维护。

## 用户流程

1. 打开设备页即看到真机及已创建模拟器，包括关机实例；平台与类型一眼可辨。
2. 可操作设备点击“打开”进入同一工作台；只读查看与取得输入权分别表达。
3. iPhone 未就绪时点“检查环境”，看到当前阻塞项、最近检测时间、可执行修复。
4. 创建 iOS 模拟器时先自动选择唯一可用 Mac；有多个可用 Mac 才展开位置选择。
5. 默认只选该 Mac 实际安装且可用的机型／runtime 组合；查看完整目录是次级入口。
6. 启动阶段可追踪；启动完成后在同一资源行显示“打开”，不新增第二条在线设备。
7. 关闭工作台仅关闭查看／释放本人的控制；不隐式关机。停止模拟器保留应用与数据。
8. 停止、重启 WDA、删除失败时保留错误与实际观察状态；由用户明确重试。

### iOS 真机：把 WDA 变成可诊断服务

检查链建议为：宿主工具链 → USB／配对／设备信任 → 开发条件 → 签名／描述文件 →
WDA 编译安装 → WDA 启动和状态 → 截图／输入能力。步骤可并行检查时不必机械串行等待。

- 不再只给出“WDA 未就绪”；输出稳定 reason_code、可读原因、下一步和证据时间。
- 详情展示 Team／证书标识和有效性，私钥、账号密码及令牌不进入页面／日志。
- 个人 Apple ID 临时签名失效或需重新签名时，基于实际检查提示，不臆测固定剩余天数。
- 区分重试检查、重启本机设备的 WDA、重新构建／安装；不提供一个含糊的“全部修复”。
- 缓存产物按源码、工具链和目标环境识别；状态检查不重复触发编译或安装。
- 不可通过 SSH 自动替代的信任／开发者模式等条件如实显示；不承诺免除 Apple 必需授权。
- 同宿主其他设备的 WDA 不应被某台设备恢复操作重启。

### iOS 模拟器：单独生命周期，统一使用入口

用户文案使用“iOS 模拟器”。它运行于 macOS/Xcode/CoreSimulator；保留内部 ios_sim 适配器。
真机与模拟器共用 WDA 工程及上层操作语义，但准备、构建和启动流程分别实现。
Simulator 构建不应要求用户填写真机 Personal Team／设备证书。

- 默认创建内容：名称、机型、已安装系统版本；宿主自动选择结果及可用资源可展开查看。
- 缺 runtime 时显示下载大小／空间来源与安装动作；大小未知就显示未知，不自动下载全部版本。
- “官方目录存在”不能作为宿主可运行证据；组合校验以选定宿主的实际工具链／runtime 为准。
- 启动显示准备实例、开机、准备 WDA、控制检查、画面检查；阶段未完成不显示可操作。
- 支持重开相同实例，应用数据保留；“复制配置”不冒充复制数据快照。
- 删除／抹掉数据必须明确目标和不可恢复影响；宿主离线时不谎报实体删除完成。
- 安装应用时检查目标平台产物兼容性；真机 IPA 不默认视为 Simulator 可安装包。
- 实例数建议基于宿主实际内存压力、CPU、磁盘和工作负载；不把代码中的经验内存常量当作容量保证。
- 宿主重连认领原实例，不通过新建一个实例掩盖恢复失败。

## 分阶段建议

| 阶段 | 范围 | 完成门槛 | 状态 |
|---|---|---|---|
| A：管理体验收敛 | F01–F04、F09/F10 的 UI 与契约；统一列表、详情、主动作、占用、异步反馈 | Android 核心流程不退化；iOS 缺条件可解释；关机资源不消失 | 已部署，部分实际交互待验收 |
| B：iOS 真机 WDA | F05、F09/F10；先环境预检，再一个真机的构建／启动／恢复闭环 | 真实 iPhone 可查看、点击、输入、释放及恢复；独立错误样例验收 | 宿主环境已就绪，真机签名未满足 |
| C：iOS 模拟器 | F06/F07、F09/F10；单 Mac、一个已安装 runtime、一个常用机型先打通 | 创建→启动→操作→停止→同实例重开，应用／数据与资源身份保留 | 核心链路已实测；完整验收见迭代记录 |
| D：iOS 体验实测 | F08；分别比较真机和模拟器画面／输入瓶颈，按结果优化 | 有基线、原始样本、改后对比及异常恢复证据 | 服务器输入／返回画面基线已采集；浏览器前台与真机待测 |

可并行准备 B/C 的环境，但验收分开；模拟器无需等真机证书问题解决。
节点调度、跨地域媒体直连、节点大盘、本轮新认证／RBAC、鸿蒙扩展暂缓。
现有测试站免登录与设备占用是不同概念；免登录不取消租约和设备服务令牌。

## 待决项

- 列表与工作台采用详情抽屉还是独立详情页：A 阶段先出可审阅原型再定。
- iOS 真机签名准备来源，以及实际 Xcode 与当前 macOS 的兼容版本：实施前核查，本文不指定未经验证的新版本。
- Simulator 首个常用机型与 runtime：优先宿主实际可安装、空间可接受的组合。
- iOS 画面是否更换媒体路径：D 阶段依据测量决定，不因 Android 已用 H.264 就直接照搬。
- 异常状态刷新是保留轮询、增加事件推送还是混用：先保证状态正确和隐藏页停用，不预先重建消息系统。
